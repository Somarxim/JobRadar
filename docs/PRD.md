# JobRadar 产品需求文档（PRD）

| 版本 | 日期 | 状态 |
|---|---|---|
| v0.2 | 2026-09-04 | 补充目标求职方向；后端栈调整见 architecture v0.2 |
| v0.1 | 2026-09-03 | 初稿 |

## 1. 背景与问题

应届毕业生求职市场存在严重的信息割裂：

- **渠道分散**：互联网（BOSS 直聘/牛客/企业官网）、央国企（国聘/中智/企业官网）、研究所（各院所官网/公众号）各自为政，无统一入口；
- **进度失控**：投递行为散落在多个平台，求职者难以回忆"在哪个平台投过什么岗位、何时投递、进行到哪一步"；
- **信息盲区**：央国企/研究所招聘信息发布渠道小众，日常浏览极易错过，且这类岗位普遍有硬性门槛（学历、专业、应届身份），需要针对性地筛选；
- **规划缺失**：缺乏工具支撑投递节奏管理（本周该投哪些、哪些快到 DDL、哪些该跟进）。

## 2. 产品目标

**双重目标：**

1. **实用目标（2026 秋招自用）**：在秋招期间（2026.09–2026.12）作为主力工具，实现 100% 投递记录留痕、DDL 零遗漏、每日发现高匹配岗位。
2. **简历目标（AI 项目背书）**：作为简历上的 AI Agent 项目，具备可演示的 Agent 能力与 MCP 协议实践，技术叙事完整。

**非目标（Out of Scope）：**

- ❌ 自动投递/代投（合规风险，且各平台反爬严格）
- ❌ 简历代写（辅助建议可以做，代写不做）
- ❌ 爬取需登录态的数据（BOSS 等平台的登录后数据不碰，只走插件辅助人工浏览场景）
- ❌ 多用户/SaaS 化（本地单用户优先，架构不堵死未来扩展）

## 3. 目标用户与核心场景

**用户**：2026 届应届毕业生（首要用户：作者本人）。

**目标求职方向**（决定匹配词表与爬虫源设计，详见 [target-sources.md](target-sources.md)）：
- 目标单位：军工研究所（航天科技/航天科工/航空工业/中国航发/中国兵器）、运营商（中国电信/移动）、银行（各行软开中心）为主战场，互联网为并行线；
- 目标岗位：Agent 研发 / AI 全栈开发 / 信息系统开发与维护 / 传统后端开发（Python 为主，兼收 Java/嵌入式）。
- 注：军工所少有"Agent 研发"岗位名，检索与匹配需兼容"信息系统开发与维护""软件研发"等传统表述。

### 核心用户流程

**流程 A：浏览收藏（日常使用，碎片化）**
```
在 BOSS/牛客/国企官网浏览岗位
→ 点击 Chrome 插件「收藏到 JobRadar」
→ 插件提取页面信息（LLM 清洗为结构化数据）入库
→ 岗位出现在「岗位库-待评估」列表
```

**流程 B：每日发现（信息盲区消除）**
```
爬虫每日定时扫描国聘网/研究所官网/牛客
→ 新岗位去重、结构化入库
→ 匹配 Agent 粗筛 + 精评
→ Dashboard「今日推荐」展示 Top N 高匹配岗位（含推荐理由）
→ 用户一键「加入计划」或「忽略」
```

**流程 C：投递规划与执行**
```
从岗位库/推荐中选定目标 → 设置计划投递日期与优先级
→ 每日待办清单提示今日应投岗位
→ 投递后在看板拖拽到「已投递」（记录渠道、时间）
→ DDL 倒计时提醒
```

**流程 D：进度跟踪与复盘**
```
笔试/面试通知到达 → 更新卡片状态（自动留痕阶段历史）
→ 日历视图查看本周笔试面试安排
→ 周末查看 Dashboard 漏斗与周报，调整下周投递策略
```

**流程 E：自然语言管理（MCP 亮点场景）**
```
在 Claude Desktop 中说：
「我今天在官网投了航天 X 所的软件工程师岗，帮我记一下」
「帮我查一下这周有哪些 DDL」
「这个岗位和我的简历匹配吗，帮我分析一下」
→ MCP Server 调用对应工具完成操作并回复
```

## 4. 功能需求（按优先级分级）

### P0 —— MVP（Week 1，秋招刚需）

| # | 功能 | 说明 |
|---|---|---|
| F1 | 岗位手动录入 | 表单录入 + JD 文本粘贴（LLM 辅助解析结构化） |
| F2 | 岗位库列表 | 搜索（关键字/公司/地点）、筛选（公司类型/状态）、排序 |
| F3 | 投递看板 | 按阶段分列，卡片拖拽流转，显示公司/岗位/DDL/优先级 |
| F4 | 投递记录 | 每次状态变更自动记录时间与备注（阶段历史） |
| F5 | 日历视图 | 展示 DDL、笔试、面试、计划投递日 |
| F6 | 基础 Dashboard | 各阶段数量统计、近 7 天投递数、DDL 倒计时列表 |

### P1 —— 核心体验（Week 2–3）

| # | 功能 | 说明 |
|---|---|---|
| F7 | Chrome 插件收藏 | 一键提取当前页岗位信息，推送至本地 API |
| F8 | 简历管理 | PDF 上传、LLM 解析为结构化 JSON、多版本支持 |
| F9 | 匹配 Agent | 简历-JD 双阶段匹配，输出匹配分+硬性条件核对+建议 |
| F10 | 定向爬虫 v1 | 国聘网 + 3–5 个研究所/国企官网，每日定时增量 |
| F11 | 每日推荐 | 新岗位匹配排序，Dashboard 推送 Top 5，支持接受/忽略反馈 |
| F12 | 投递规划 | 公司目标分级（dream/target/backup）、周投递目标、计划 vs 实际 |
| F13 | 全文+语义搜索 | FTS5 全文检索 + 向量语义搜索混合 |

### P2 —— 亮点与打磨（Week 4+）

| # | 功能 | 说明 |
|---|---|---|
| F14 | MCP Server | 暴露 search/add/apply/update/today/report 等工具，接 Claude Desktop |

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 部署 | 本地单机运行，一条命令启动；数据存本地 SQLite |
| 隐私 | 简历等敏感数据不出本机（LLM 调用仅发送必要字段，可配置脱敏） |
| 性能 | 岗位库万级规模下，列表/搜索响应 < 300ms；向量检索 < 500ms |
| 成本 | LLM 日调用成本 < ¥1（匹配精评仅对粗筛 Top N 调用） |
| 可演示 | 核心 Agent 流程可在 3 分钟内完成现场演示（简历面试场景） |

## 6. 成功度量

**自用维度：**
- 秋招期间投递记录留痕率 100%（所有投递都进了系统）
- DDL 遗漏数 = 0
- 每日推荐中「确实不知道这个岗位在招人」的发现数 ≥ 1/周

**简历维度：**
- 可运行、可演示（录屏 + 现场 demo）
- 技术叙事闭环：多源采集管道 + 双阶段匹配引擎 + MCP Server 工具化
- 有可量化数字：聚合 N 个信息源、日均处理 M 条岗位、匹配准确率人工抽检 ≥ X%
