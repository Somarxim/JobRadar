W1 前端（roadmap W1 第五、六项）：骨架 + 四个核心页面 + 仪表盘。

- **骨架**：Vite 8 + React 19 + TypeScript 6 + Tailwind CSS v4（`@tailwindcss/vite` 插件）+ React Router 7

  - `JobsPage`：关键字/公司类型/阶段筛选 + 排序 + 分页表格 + 两个录入对话框（手动录入 / 粘贴导入）

## 技术概念卡

### Vite 开发代理（server.proxy）
- 是什么：dev server 把 /api 请求转发到后端，浏览器视角始终是同源（localhost:5173）
- 项目里哪里用了：vite.config.ts；前端代码里 fetch('/api/...') 无需关心后端地址
- 面试可能追问：跨域与同源策略是什么？代理和 CORS 各解决了什么问题？（代理避开浏览器跨域；CORS 是浏览器放行机制）

### Tailwind v4 的 CSS-first 配置
- 是什么：v4 不再需要 tailwind.config.js，主题用 CSS 的 @theme 指令声明
- 项目里哪里用了：index.css 中 @theme inline 把 shadcn 的 CSS 变量映射为 Tailwind 色板
- 面试可能追问：CSS 变量做设计 token 的好处？（运行时换肤、组件与配色解耦）

### dnd-kit（拖拽）
- 是什么：React 拖拽库，useDraggable/useDroppable hooks 抽象拖拽源与放置目标
- 项目里哪里用了：BoardPage 看板列（droppable）+ 卡片（draggable），onDragEnd 调流转 API
- 面试可能追问：为什么不直接用 HTML5 drag API？（与 React 状态模型不匹配、无触摸支持、样式反馈繁琐）

### record 对齐后端契约 + SNAKE_CASE 序列化
- 是什么：前端 TS 类型直接按 API 的 snake_case 字段书写（company_name 而非 companyName）
- 项目里哪里用了：api/types.ts
- 面试可能追问：为什么不让后端返回 camelCase？（契约即文档，api-design.md 定 snake_case 与 SQL 列名一致，减少心智翻译）
