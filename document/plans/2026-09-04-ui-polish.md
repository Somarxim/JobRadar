## 改动原因

用户反馈：①岗位库无法修改已有岗位（前端漏接 PATCH）②详情页右侧空荡、空间利用率低 ③全站灰白单调、缺少视觉层次。

## 技术概念卡

### PATCH 语义与 Hibernate dirty checking
- 是什么：PATCH = 部分更新，约定「请求里 null 的字段保持原值」；后端在 @Transactional 内修改托管实体字段，事务提交时 Hibernate 脏检查自动生成 UPDATE，无需显式 save
- 项目里哪里用了：`JobService.patch`（注释已写明）；前端编辑表单据此把空串转 null 提交，避免把字段误清空
- 面试可能追问：PUT 和 PATCH 的区别？（PUT 幂等全量替换 vs PATCH 部分更新）；脏检查的性能代价？（快照比对，字段多时有开销，可用 @DynamicUpdate 只更新变更列）

### 设计令牌字典（Design Token Dictionary）
- 是什么：把「枚举值 → 文案 + 颜色」收敛到一个 META 字典，label 映射由字典派生，全站共用
- 项目里哪里用了：`STAGE_META` / `COMPANY_TYPE_META` / `CHANNEL_LABELS`，表格、看板、详情、仪表盘、时间线五处共用
- 面试可能追问：为什么不让后端直接返回中文/颜色？（展示与数据解耦：改文案不动契约不迁数据；后端面向多客户端，不应感知 UI 主题）
