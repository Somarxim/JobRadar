## 改动内容

W1 第三轮反馈（用户四条意见）：

1. **详情页栏位对调**：左主栏 = 投递状态（高频操作置顶）→ 职位描述 → 岗位信息；右侧边栏 = AI 匹配报告（固定高度在上）→ 流转记录（高度不定在下）。原因：流转记录通常很短，放主栏空荡；且记录变长不能把匹配报告顶出首屏
2. **回退流转守卫**：`labels.ts` 定义 `STAGE_ORDER`（主线 collected→…→offer，rejected/withdrawn 为终态不参与排序）+ `isRollback()`；主线逆向流转（如 面试→笔试）时弹 `TransitionConfirmDialog`，提供「仍然回退 / 标记未通过 / 标记已放弃 / 取消」四个选项。详情页按钮与看板拖拽均接入。校验放前端而非后端：后端保持宽松状态机语义（插件/MCP 等自动化入口不应被 UI 规则卡死），交互引导由前端负责
3. **「投递目标」统计口径修正**：原口径是 `weekly_goals` 表目标值、无记录默认 10（用户从未配置却看到目标数，困惑）。改为「累计投递（在途）」= funnel 中 applied+written_test+interview+offer 四档计数之和，直接来自状态统计；rejected/withdrawn 为已归档终态不计入。进度条移除，「本周新投递」保留为副行。纯前端改动，后端契约不变
4. **整体配色去黑白化**：
   - `index.css` 主题令牌：`--primary` 从 zinc 近黑 `oklch(0.21 0.006 285)` 改为蓝色 `oklch(0.488 0.243 264.376)`（shadcn blue 主题值），ring 同步；muted/accent 带极淡蓝调；dark 模式同步亮蓝。按钮、导航选中态、链接、进度条等所有引用 primary 的位置一步换色
   - 侧边栏深色化（slate-900 底 + 主色选中项 + slate-400 文字），与白色内容区形成经典 dashboard 对比
   - 仪表盘卡片标题加彩色图标（投递进展-蓝 TrendingUp / DDL-红 AlarmClock / 待办-琥珀 ListTodo）；看板列头加阶段色点；AI 占位卡淡紫底色

## 改动原因

用户反馈：①流转记录短、放主栏空荡，匹配报告应在不定高的记录之上 ②面试→笔试等回退流转不合逻辑，应提示并引导归档 ③投递目标数字来源不明（默认值），应按「已投递及后续阶段」实际统计 ④整体纯黑白压抑，需要主题色与彩色图标。

## 技术概念卡

### 前端守卫 vs 后端状态机（宽松契约 + 交互引导）
- 是什么：后端不限制流转方向（宽松状态机），前端在用户操作路径上做合理性检测与引导
- 项目里哪里用了：`isRollback` + `TransitionConfirmDialog`（详情页/看板共用）
- 面试可能追问：为什么不在后端拦截？（契约对多端开放：插件/MCP 自动化入口可能确有重开流程的需求；UI 规则卡死会破坏契约通用性。引导在前端、数据在后端，职责分层）

### 设计令牌换肤（CSS 变量 + 语义色）
- 是什么：组件只引用语义色（primary/muted），具体色值集中在 :root CSS 变量；换肤改一处全局生效
- 项目里哪里用了：`index.css` @theme 令牌；本次仅改 `--primary`/`--ring` 等 4 个值，全站主色从黑变蓝
- 面试可能追问：Tailwind v4 的 @theme 与 v3 tailwind.config 的区别？（CSS-first 配置，令牌即 CSS 变量，运行时可被 JS/深色模式覆盖）
