## 改动内容

W1 业务 API（roadmap W1 第三、四项）：jobs CRUD + 手动录入/导入 + applications 流转 + events + dashboard/summary + dashboard/calendar，共 12 个端点。

**core 模块**（不依赖 HTTP，可被 MCP 宿主复用）：

- `exception/`：BizException 基类 + NotFound/Conflict/BadRequest/Unprocessable 四个语义异常
- `dto/`：record 形式的 API 契约对象（JobDtos/ApplicationDtos/DashboardDtos/PageResponse）
- `service/JobService`：Specification 动态搜索（q/company_type/tier/city/stage/deadline_before + 排序）+ 手动录入 + ingest 导入（幂等）+ 部分更新
- `service/ApplicationService`：看板分组 / 创建（409 防重复收藏）/ 部分更新 / 状态流转（事件留痕 + applied_at 回填 + 同阶段幂等）/ 事件时间线
- `service/DashboardService`：summary（漏斗/本周/DDL倒计时/待办）+ calendar（deadline/planned/next_action 三类事件）
- `util/DedupeHash`：company+title+city 归一化 SHA-256 去重指纹
- Repository 增补区间查询与批量装配方法（findByJobIdIn 等）

**app 模块**：

- `web/`：JobController / ApplicationController / DashboardController（薄控制器，只接参+校验+转发）
- `web/GlobalExceptionHandler`：@RestControllerAdvice 集中映射 400/404/409/422 → `{"detail":...}`
- `config/JobRadarProperties`：@ConfigurationProperties 绑定 jobradar.* 配置段
- `config/WebConfig`：CORS 放行 vite dev + `chrome-extension://*` 模式
- `config/LocalTokenFilter`：写操作鉴权（受信 Origin 放行，其余须带 X-Local-Token）
- `application.yml`：Jackson 全局 SNAKE_CASE + 枚举大小写宽容反序列化

按 roadmap W1「API：jobs CRUD + 手动录入/粘贴导入 + applications 流转 + events」与「dashboard/summary + dashboard/calendar」落地，支撑前端骨架联调。

## 技术概念卡

### @Transactional 的事务边界与脏检查
- 是什么：声明式事务，方法进入开启、返回提交、异常回滚；事务内托管实体的字段变更自动同步（无需 save）
- 项目里哪里用了：全部 Service 方法；JobService.patch 依赖脏检查；ApplicationService.transition 一次事务写两张表
- 面试可能追问：readOnly=true 有什么用？失效场景（自调用/private/异常被吞）？

### 为什么 Service 返回 DTO 而不是实体
- 是什么：DTO = 只装数据的传输对象（这里用 Java record）
- 项目里哪里用了：core/dto/*；所有 Service 在事务内装配 DTO 后返回
- 面试可能追问：直接返回实体会怎样？（OSIV 关闭下事务外访问懒加载字段抛 LazyInitializationException；表结构泄露为 API 契约）；record 和 class 做 DTO 的区别？

### Specification（JPA Criteria 动态查询）
- 是什么：把查询条件封装为可组合的对象，Criteria API 类型安全拼装 WHERE
- 项目里哪里用了：JobService.search 的 6 个可选筛选条件 + stage EXISTS 子查询
- 面试可能追问：为什么不用 join 筛 stage？（一对多 join 产生重复行，分页 total 失真）；和 QueryDSL 的取舍？

### @ConfigurationProperties vs @Value
- 是什么：成组配置绑定成类型安全对象 vs 单个值注入
- 项目里哪里用了：JobRadarProperties 绑定 jobradar.security/cors；application.yml 注释原承诺"后续提交绑定"本提交兑现
- 面试可能追问：宽松绑定规则（kebab-case ↔ camelCase）？配置优先级（环境变量 > yml）？

### Jackson 契约定制（SNAKE_CASE / 枚举 / 时间）
- 是什么：通过 application.yml 全局定制序列化，而非逐字段注解
- 项目里哪里用了：property-naming-strategy=SNAKE_CASE（契约 snake_case）、accept-case-insensitive-enums（入参小写枚举）、枚举 @JsonValue（出参小写）、Boot 默认 ISO-8601 时间输出
- 面试可能追问：@JsonValue 与 @Enumerated 是两个层面（JSON 序列化 vs JPA 持久化），本项目枚举"三段桥接"：DB 小写（Converter）↔ Java 大写 ↔ JSON 小写（@JsonValue）

### CSRF 与本地 API 的简易鉴权
- 是什么：浏览器跨站"简单请求"会真实到达服务器（CORS 只拦读不拦写），本地服务需防恶意网页写操作
- 项目里哪里用了：LocalTokenFilter——受信 Origin 放行 + 其余写请求校验 X-Local-Token
- 面试可能追问：为什么不引入 Spring Security？（单用户本地应用，过滤器即可覆盖，依赖最小）；OncePerRequestFilter 解决什么？

## 影响范围
